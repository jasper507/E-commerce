## 1. 本片确认了什么

项目拥有者明确选择：沿用现有会话等待上限，不新增秒杀专用 5 秒配置。
本地预检 MySQL 8.4.10 / READ-COMMITTED，SESSION `innodb_lock_wait_timeout=50` 秒，
`innodb_rollback_on_timeout=false`，死锁检测开启。50 秒是本机观察，不保证所有部署环境都是该值。
它限制相关 InnoDB 行锁等待，不能称为整个下单或 HTTP 请求的 50 秒截止时间。
HTTP 接入前再确定顾客可接受的等待预算，本片不改变普通购物车或全局连接配置。

另一方案是在秒杀调用前临时设置 5 秒并恢复会话值，但会增加 SQL 和连接恢复失败处理。
本片选择先保持最小实现，理解实际数据库异常和业务回滚；没有引入这套会话管理。

## 2. 正式库存步骤

原下单流程不变：User 串行化、Key 重放、地址归属、活动/价格校验、订单与资格、库存步骤、预占与流水、提交。
正式 `_reserve_flash_sale_inventory()` 现在在 SQL 内判断 available>=1，并同时写 available-1、reserved+1。
1 行后继续 GET Inventory；0 行按原约定返回 `insufficient_stock / 409`，也涵盖库存记录缺失。
库存数量由条件更新保护；资格唯一约束与幂等键仍分别承担限购和重放，不能删掉。

在库存 UPDATE 的 DatabaseError 分支中，只识别 1205 和 1213，转换为现有 `stock_busy / 409`，保留原异常为 cause。
它们不会被解释成 0 行或库存不足。其他错误继续上抛，没有自动重试。
这个转换仅覆盖库存 UPDATE；前面的 User/Address 锁或其他语句错误没有被扩展为同一合同。
完整订单并非一条 SQL，条件更新之后仍须完成其他关联事实。

## 3. 为什么 UPDATE 超时还需要整个业务回滚

假设初始 available=1、reserved=0。另一个连接先锁住库存，当前请求已经写入：

| 未提交事实 | 库存 UPDATE 开始前 |
| --- | --- |
| Order / OrderItem / AddressSnapshot / FlashSalePurchase | 各 1 条 |
| InventoryReservation / InventoryMovement | 各 0 条 |
| 当前请求的库存修改 | 尚未成功 |

当前 UPDATE 等不到锁，数据库抛 1205。默认 MySQL 可能仅撤销当前语句，因此之前订单与资格不能靠它自动消失。
应用把异常向外抛，让它离开 `create_flash_sale_order()` 的 atomic 边界，下单业务事实一并回滚。
返回错误时必须核对六类事实全为 0、库存仍为 1/0、原 Key 没有留下订单映射。
不能在失败的业务事务里吞掉错误继续提交，或只重跑 UPDATE。

官方语义见 [InnoDB 错误处理](https://dev.mysql.com/doc/refman/8.4/en/innodb-error-handling.html)。
死锁错误会导致受害事务回滚；本片的真实实验只制造锁等待超时，没有声称真实复现死锁。

## 4. 怎样证明这是实际数据库超时

Holder（持锁连接）只锁 Inventory，不创建订单；Contender（竞争连接）执行完整正式下单。
第三个 Observer（观察连接）按竞争连接的 CONNECTION_ID，只读观察 PROCESSLIST 中尚未结束的库存 UPDATE。
竞争连接只在隔离测试里把自己的等待值设为 1 秒，退出后关闭，不修改正式配置。

必须保存三个不同 CID、UPDATE SQL、执行前当前事务内的事实、实际 1205、cause、失败后的 ORM 快照。
耗时只能辅助解释；只说“等了一秒”不能证明发生 MySQL 锁等待超时。
持锁者在竞争请求结束并检查回滚前保持锁，随后放行；原 Key 再调用应新建一单，同 Key 再重放应返回同一单。
最终预占和 RESERVE 流水各一次，库存 0/1，失败顾客没有半张订单或残留资格。

1213 和未知数据库错误的注入检查只证明转换与透传分支。
注入 1213 不等于真实循环死锁；注入 2006 不等于实际断开网络或数据库，也不能证明提交不确定性的恢复。

## 5. 为什么保留历史 NOWAIT 对照

正式实现切换以后，如果两个实验标签仍调用同一个默认函数，所谓“两种策略”就失真。
因此原 NOWAIT 函数只迁到测试中，旧 NOWAIT 测试显式选用；条件 UPDATE 测试直接调用正式实现。
原断言与历史证据不改，旧候选副本移除，避免两份条件逻辑漂移。
原负载实验仍须显式开启，本片不重跑其 24 批矩阵；过去的数字是过去源码和环境下的证据。
