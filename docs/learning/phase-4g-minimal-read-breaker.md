## 问题与最小选择

Phase 4F 已观察到持续慢故障第二轮仍有 6 次 GET、6 次超时。两个故障
回源名额限制降级并发，但每个请求仍先等待 Redis。读取熔断负责暂时
绕过失败依赖，继续配合既有名额；满员立即 503 的规则不重新改变。

用户接受一次网络失败、1 秒冷却作为实验候选。这个选择易于理解和验证，
代价是一次瞬时故障也会让本进程暂时回源。替代方案是保持现有短超时：
简单、每请求及时发现恢复，但持续故障继续付出等待成本。

用户要求控制首个项目的范围：最小熔断 → 穿透 → 多 Key 雪崩 → 整理
缓存故事 → 支付。保留必要正确性，不引入通用框架或新的治理阶段。

## 三状态与六个请求

- Closed：正常允许操作，一次指定连接/超时异常后进入 Open。
- Open：冷却内跳过操作。它表示最近失败、暂时不尝试，不能证明 Redis
  此刻仍然故障。跳过会标记降级并申请已有回源名额。
- Half-open：冷却结束后的第一个操作成为探测者；它还在执行时，其他
  操作立即跳过，不等待其结果。探测成功恢复 Closed，网络失败重新冷却。

假设冷却结束后六个请求到来，并保持第一个探测操作还未结束：一个探测，
另外五个跳过并回源。若探测已成功结束，随后取得许可的请求可正常读取；
不能说任意六并发都固定只有一次 Redis 操作。

本实现使用 Monotonic Clock（单调时钟：系统时间调整不影响经过时间）
判断冷却，用短 Lock（锁：防止线程同时修改状态）登记唯一探测者。
Redis 操作在锁外，SQL 和 SingleFlight 等待也不应放入这个操作。

## 旧操作晚到：只记一个状态轮次

```text
1. A 在 Closed 开始读取，记下轮次 0，但迟迟没有结果。
2. B 在轮次 0 超时，打开熔断；当前轮次变成 1。
3. A 随后返回成功，仍属于轮次 0。
4. A 可以获得自己的返回值，但不能改变轮次 1 的 Open。
```

Epoch（状态轮次：标明结果属于哪一轮）只用于防止旧结果改写新状态。
另一方向也一样：新探测恢复正常后，旧操作晚到失败不能再次打开熔断。
不取消在途操作，不把旧请求返回值吞掉。

## 异常与操作单位

指定 redis.exceptions.ConnectionError/TimeoutError 触发故障规则，排除
已知的鉴权、权限、连接池满、外部鉴权和服务器加载期错误子类；这些类
也继承 ConnectionError，不能仅凭父类名字说它们都是网络故障。
普通 ValueError、UnicodeError、ResponseError 及共享等待 TimeoutError
不在 Closed 打开熔断；原始异常继续交给调用方。半开探测发生其他异常
时，保守地回到 Open 再冷却，释放资格；不声称通信成功或网络失败。
异常清理覆盖 BaseException，避免中断后一直占着探测资格。

回调成功返回 None 也算操作成功。代号的 GET → 可选
SET NX → GET 作为一组逻辑操作，每次详情 GET 另算一个操作；JSON
解析在读取之外。正常 miss、非法代号或坏 JSON 不直接证明网络坏了。
404、SQL 异常、503 与 SingleFlight 等待超时不作为 Redis 网络失败。

回填 SET 与提交后换代独立；读熔断不能跳过失效，也不能修复恢复旧价。
门槛固定为 1，没有额外失败计数、动态配置或后台探测。

## 第二步：怎样接入，实际看到了什么

cache.py 只在两处调用 detail_reads.run(operation)：请求开始时捕获代号，
以及每次详情 GET。RedisReadSkipped 表示本次不尝试读取，随后使用现有
available=False/degraded=True 降级规则，原视图无需改写。

```text
请求 → 熔断器决定是否读取代号
├─ Open / 已有半开探测者 → 跳过 → 申请 2 个名额
│  ├─ 满员 → 503，零业务 SQL
│  └─ 取得 → MySQL 上架检查、详情加载 → 归还名额
└─ 允许 → Redis 读代号 → MySQL 上架检查 → 熔断器决定是否读详情
   └─ 此时跳过或故障 → 保护后续 SKU 加载；已经发生的上架 SQL 无法撤回
```

实际继续故障波次各 6 请求：短超时方案 6 GET/6 超时、响应 p50
111.665ms；熔断方案 0 GET/0 超时、p50 2.147ms。两方案回源名额峰值
均为 2，成功内容都正确。首轮仍各有 6 个在途读取超时，不能取消它们。
这些小样本来自受控实验，不是生产性能倍数或容量结论。

纯状态补充异常分类后实际 17 passed in 0.14s；新增 API 边界与真实
失败探测目标 10 passed in 8.70s；目录整体 99 passed、6 subtests
passed in 37.63s。真实失败探测允许连接错误或连接超时：Windows 本次
实际报 TimeoutError，先前只断言 ConnectionError 的测试已纠正。

这里只恢复通信；换代失败留下的旧价边界仍保留。提交后失效 SET 独立，
回填 SET 失败保留正常响应。健康慢加载仍按原等待策略，不触发读熔断。
