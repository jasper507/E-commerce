## 本片前后变化

开始前：交易和三条技术主线已有多阶段证据，但旧总纲的勾选、当前状态与后续决定混在一起；本轮尚未核实最终提交的 CI。本文把版本、当前回归、历史中间件实验和本期边界对齐，不新增业务功能。

完成后：收尾按“可运行的交易主链＋三个可解释的技术故事＋已有隔离扩展＋基础部署”判断；个人掌握另行验收。历史实验保留原日期和结果，不因为此次收尾就变成最新版本重新运行。

## 1. 现在闭环由谁负责

浏览和搜索给出商品提示；登录确定身份，购物车和地址表达购买意图。建单时重新检查归属、金额与库存，订单快照和库存预占在同一 MySQL 事务提交。Mock 支付确认后核销，模拟发货后收货完成。取消/到期释放和迟到付款退款模拟处理旁路失败。

MySQL 保存订单、库存和支付事实。Redis 商品详情缓存减少加载成本；Lua 准入限制尝试进入秒杀事务的速率；RabbitMQ/Celery 把已入箱的支付事件交给后台执行；ES 提供搜索候选，再由 MySQL 重新确认当前可见性和摘要。这些机制不能互相替代。

## 2. 最终验收最容易混淆什么

**CI（持续集成，每次推送自动检查代码）通过，只证明工作流真正执行的范围。** 当前工作流有 MySQL、配置检查、迁移和默认 pytest，没有 Redis/RabbitMQ/ES 服务，也没有前端构建步骤。这里另跑前端 `build`，同时完成 Vue/TypeScript 类型检查与 Vite 产物生成。

**默认测试的 skipped（未执行）不是通过，也不等于模块没做。** 真实中间件和性能实验需要明确 URL 或实验开关。日常回归检查本次组合后的业务规则；历史真实服务记录说明对应场景的运行语义。两类证据并列，不能把它们的数量相加后说本轮全部运行。

**实现、启用、实测是三件事。** Lua 已实现并实测，但本机部署没有启用；ES 的原型、候选读 API 和别名切换已实测，但只接受测试库来源，顾客前端仍走 MySQL 搜索；MQ 已真实验证，默认支付仍同步，补漏仍需人工触发。

## 3. 为什么采用一次默认回归＋历史证据核对

最终默认回归覆盖账户权限、购物车/地址、订单与库存、付款/关闭/退款模拟/履约、秒杀和纯规则等。测试库独占创建、迁移、销毁；默认连接使用不存在的占位库，避免把开发库写入路径带入回归。运行前后只读比较开发表的行摘要，敏感行及摘要保存在 Git 外。

历史证据核对还检查对应提交是否在当前历史中、相关实现后来改了什么。比如秒杀负载实验发生在正式条件 UPDATE 落地之前，它支持选型，但不能说今天又测了一遍；后续正式服务、HTTP 和浏览器证据补齐落地路径。源码发生变化时，必须结合变化理由和本次回归判断原结论还能支持到哪里。

替代方案是把所有服务、杀 Worker、离线故障和大数据压测重新运行。它能提供更近的实验日期，但共享测试库需要严格串行，耗时更长；没有相关新改动或证据失配时，收益不足以挤占整体理解与基础学习。本片以必要回归和清楚的证据边界为停止条件。

## 4. 可以讲到哪里，哪些话应留在候选里

| 面试主张 | 当前能支持的范围 | 剩余代价或边界 |
| --- | --- | --- |
| 防超卖、幂等与完整事务 | 隔离 MySQL 并发、失败回滚、原 Key 重放与交易回归 | 不保证没有死锁；有些异常是注入而非真实故障 |
| 缓存一致性与故障保护 | 分代隔离旧回填、负缓存、请求合并、回源预算和熔断 | 不是强一致；合并与回源名额按进程计算 |
| 支付事件异步处理与恢复 | 真实 Broker/Worker、重复消费、有界重试、租约和人工补漏 | 不是消息恰好一次执行，也没有周期自动接管 |
| Lua 保护数据库 | 24 次尝试对照中，订单事务由 24 次降至 4 次 | 20 次被拒，不能说同样成交量提速；不预扣库存 |
| ES 可重建查询副本 | 测试来源、当前 MySQL 摘要、短页、失败 503、手动切换 | 没有自动同步、开发启用或前端完整 ES 搜索 |
| 部署流程 | Linux 镜像、Nginx/Gunicorn/MySQL、本机请求和认证验收 | 未验收公网 HTTPS、全中间件部署、更新/恢复演练 |

订单联合索引消除了相应列表排序，但 COUNT 与深 OFFSET 仍有成本。性能数字只属于记录中的本机合成数据、受控并发和测量口径，不包装成线上容量。

## 5. 本期收尾之后还剩什么

工程验收与 Learning Done（自己能够解释并修改的学习完成）分开。现在最值得补的是独立串起交易、解释三个故事和必要基础：MySQL 索引/事务/锁、缓存三类问题、HTTP/Session/CSRF、消息重复与恢复、ES 分词/倒排索引、部署请求链。

下一步先围绕[项目总览](project-current-overview-study-guide.md)复习完整交易，再按库存 → 支付/MQ → Redis/Lua → MySQL 查询 → ES → 部署复习已有问题页，最后整理简历主张。已有测试通过不代替你的理解；不因旧未勾选自动加入新模块、全服务部署或新压测。

若你之后明确要练备份恢复，可另选一次独立空库演练；否则先理解已有[运维手册](../deployment/local-operations-runbook.md)。真实数据和部署操作仍需单独说明影响并获得确认。本片不自动开始该演练或发布网站。
