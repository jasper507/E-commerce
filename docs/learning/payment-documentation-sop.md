# Project One 支付资料规范与SOP

日期：2026-10-06。适用对象：项目作者自己的学习、实验复盘和面试材料。
本页是本地规范建议，不新增架构决定、不表示已发布Wiki。SOP（标准操作流程）就是每次整理资料照着走的一组步骤。

## 资料应该分成三层

1. **学习正文**：回答为什么、怎样运行、189元订单前后值、图和少量关键代码。
2. **操作指南**：说明准备环境、命令作用、输出怎么看、失败后如何安全停止或恢复。
3. **验证记录**：保存执行日期、命令、条件、Git基点/本地变更、原始数据、成功与失败结果、结论边界。

学习页引用验证记录，验证记录链接JSON/测试源码。不要复制同一份实验数字到多个地方却遗漏日期和条件。
导航入口是[支付完整流程](payment-learning-and-interview-guide.md)，既有阶段指南仍保留，不搬迁或覆盖Redis材料。

## 每个问题页固定九项

| 顺序 | 必须回答什么 | 189元例子 |
| --- | --- | --- |
| 1 业务问题 | 谁遇到什么触发条件？ | 付款请求超时，供应商可能已经成功 |
| 2 不变量 | 无论顺序变化，什么必须保持？ | 原Attempt与189元金额不变，不再发起新付 |
| 3 流程图 | 谁调用谁，哪里提交或等待？ | Attempt提交 → Gateway → UNKNOWN → 查原引用 |
| 4 方案与替代 | 为什么选它，有什么有意义的替代？ | 统一Inbox处理，避免查单另写一套状态转换 |
| 5 核心源码 | 真实函数路径与少量关键片段 | reconcile_payment_attempt，链接完整文件 |
| 6 正常与失败例 | 输入、前后状态和副作用次数？ | 成功后PAID；再次超时仍UNKNOWN |
| 7 验证结果 | 本次执行还是历史核对，来源在哪？ | 阶段记录、目标测试、原始JSON |
| 8 剩余代价 | 什么尚未解决或未验证？ | 原库存继续占用；本地Mock无真实扣款 |
| 9 面试问答 | 用自己语言能解释什么？ | UNKNOWN为何不等于失败，为什么查原付款 |

标记使用“计划中 / 已实现 / 已实际验证 / 历史证据本次核对 / 尚未验证”。
不要把AI给出的口述答案写成作者已经掌握，也不要把渲染成功写成应用测试通过。

## 四张时序图加一张表关系图的规范

- 每张图只讲一个主问题，使用189元订单、库存20→19/1→19/0的固定例子。
- 从左到右明确参与者：顾客/API/MySQL/Gateway/MQ/Worker；从上到下写执行顺序。

## 学习和记录的SOP

1. **选一个问题。** 先看真实源码与现有证据，避免把旧待办当新需求；写输入、输出与应保持的事实。
2. **先讲前后值。** 用原189元订单说明状态、库存、尝试次数；不确定规则先讨论，不能靠AI同时编代码和测试预期。
3. **对照源码画图。** 标事务/网络/锁边界，列一个替代方案及代价，摘少量关键代码。
4. **决定是否需要新实验。** 已有证据够就引用并注明日期；规则变化或未验证风险才运行针对性测试。
5. **记录事实和限制。** 保存命令、环境、失败修正、终值与原始数据；汇总测试结果不能冒充QPS或业务延迟。
6. **自己解释。** 能讲清为什么、怎样验证、代价和一个失败场景；暂不要求闭卷手写整套模块。
7. **归档与复查。** 更新问题入口/证据链接；本地材料确认后按指定Wiki位置发布并读回核对。

## 涉及运行实验时的操作SOP

本节仅是执行前检查顺序，不表示本次已经运行实验。

1. 读`git status`与目标测试。先确认命令是否会创建/迁移/销毁数据库、停止Worker或清理队列。
2. 使用专用`test_project_one`与本机3307 MySQL；MQ实验使用专用Broker/队列和test Worker。
   共享测试库的pytest进程不能并行运行；先按对应阶段指南隔离Worker，避免异步连接干扰建库。
3. 普通规则测试、真实MySQL竞争、真实MQ实验分开运行。按阶段指南设置明确开关；
   skip要单独报告，eager或mock不能代替真实投递/进程中断证据。
4. 只做对应实验授权的测试清理，不操作开发库、真实缓存、真实资金或外部供应商。
   C4原未ACK消息要保留用于重投证据，不能套用其他阶段的清队列步骤。
5. 保存原输出与环境，检查Order、Attempt、Event、Reservation、Movement和Refund终值。
   发生失败先解释第一个错误，不通过修改预期或放松规则掩盖失败。
6. 按对应实验恢复测试组件，报告Worker状态与限制；新增实现做最小回归，文档改动做链接/源码摘录/图渲染检查。

具体命令以[5C验证指南](phase-5c1-payment-mq-study-guide.md)、
[C4中断指南](phase-5c4-payment-worker-recovery-study-guide.md)、
[5D并发指南](phase-5d-payment-expiration-concurrency-study-guide.md)为准，避免维护第二套容易过期的命令。
